# Native action conformance cases

Owner: `content`, task `native-action-fixtures`. Baseline:
`6049cdf63e36e303327235834f23a798aa5a82c1`, protocol 6.

These fixtures describe existing daemon, web and TUI behavior before shared
client extraction. They do not define a native action API or grant device
permissions. Future native scope/confirmation and outcome records need separate
vectors tied to the approved architecture. The gateway device column remains
`pending native-gateway-contract` for each of the decided `Read`, `Control` and
`Terminal` tiers. `Read` is the default; the other grants are separate host-side
decisions. Their method mapping belongs to `notes/native-gateway.md` after
review; this corpus makes no method-per-tier assignment.

## Reading the corpus

Each `.jsonl` line is one independent case. `id` is stable across consumers;
`layer` names the behavior being checked. `context_ref` selects a record in
`contexts.json`; `given` shallowly replaces its named fields. Case input and
expected output use fixture notation, not a proposed RPC or FFI interface.

`source_refs` resolve through `sources.json` to `path`, `line` and `anchor` in
the current integrated source tree. The baseline commit identifies the behavior
being preserved; anchors follow moved or reformatted definitions after portable
extraction. References identify the wire variant, authorization/domain check and
user-facing behavior. Parser-only and local navigation cases have no wire
variant. The checker rejects outdated anchors so source relocation is updated
explicitly without changing the behavior baseline.

Shared web policy `5333e1e7` relocates four command/connection references. Their
active `source_commit` identifies that reviewed source, including `timeoutFor`
in the generated module. `reference_history` retains the prior baseline path,
line and anchor for each relocation. Case inputs, expected outputs, reference
IDs and wire byte goldens remain unchanged.

| Layer | Input | Expected observation |
| --- | --- | --- |
| `compose` | Arguments to `operations.submit` | Outgoing call, draft `keep` result |
| `command`, `slash` | `run(name, rest, context)` or `slashCommand(text)` | Pure effect/error or parsed pair |
| `action`, `operation` | Existing entry name and arguments | RPC/no call, pending/draft/status outcome |
| `question_dialog`, `model_dialog`, `confirmation` | Existing UI interaction | Call/no call and dialog outcome |
| `wire` | Full `Request` with numeric envelope `id` | Canonical `Call` or decoding rejection |
| `daemon` | Existing method and params after authentication | Partial result facts or exact `RpcError` |
| `index`, `admission` | Index call or workspace admission | Real server refusal |
| `workspace` | Current choice, route or switch operation | Navigation and connection-state facts |

Expected `call`/`calls` specify exact browser-supplied method/params. Expected
result objects assert only listed fields; IDs/timestamps generated by the
daemon are deliberately not guessed. `body_suffix` allows the daemon's bounded
question quote before the trimmed answer. `response` and `events` are supplied
transport observations, not operations. The fixed `random_bytes` context makes
the current browser message ID `w-0102030405060708` reproducible.

Contexts retain IDs from `crates/crew/tests/fixtures/web/snapshot.json`, the
`m-9001` question in `pushes.jsonl` and the listing in `multi.json`. A daemon
harness seeds the snapshot's agents/tasks, then applies context and `given`
facts; `process_alive` describes its fake process backend. Stored-message cases
seed a prior message with the listed fields and recipients. These fixtures use
no credentials and send no live messages or destructive calls.

## Behavior that must remain distinct

`capabilities.json` is the machine-readable action/confirmation table. Trusted
Unix operator, web workspace, web index and dashboard control socket are
different channels. Browser sessions can mutate every joined workspace; there
is no server read-only role. The client becomes read-only when its index or
selected workspace is not live. RPC variants without a dashboard surface and
agent-only tools are listed once as excluded, not offered as new client actions.

There are four current confirmations: `kill`, `restart-fresh`,
`restart-paused`, `stop`. Cancel/Escape sends nothing. Confirmation is owned by
the client, with no daemon confirmation field. A removed target can therefore
reach the daemon and return `not_found`; this baseline does not claim the future
native capability revalidation already exists.

`agent_resume` continues a manually suspended process. `resume` handles usage
limits; `agents: []` means all eligible limited agents, and `restart: true`
restarts their processes while resuming conversations. `agent_restart_fresh`
discards the old conversation. A `send` with `type: task` is a message, not task
creation; current task details offer read/navigation/copy controls.
For agents, `done` is a live completion state; only `failed` and `stopped` are
terminal process states.

Message bodies retain whitespace and are limited by UTF-8 bytes. Answers are
trimmed by the daemon. The source's six options/200 characters constrain
question producers, not freeform answer length. Spec IDs and client-chosen
message IDs have different validators. No extra target normalization is added.
The default message limit remains 65,536 bytes; `send-utf8-limit` uses the
existing configurable lower limit of 8 bytes to exercise a UTF-8 boundary
without storing a large repeated payload.

Preserve command-like text behavior: unknown slash commands remain drafts,
absolute paths are messages, and one leading space escapes a command. The
existing answer dialog refuses command-like text on Enter but accepts literal
text from its Send button. These cases record that distinction for explicit
review rather than silently imposing a new policy.

Only `send` retries after a closed connection, once the same workspace link
returns, using the identical client-chosen ID. A duplicate ID from the same
sender returns the original message even when new content differs. A timeout
does not replay a message or another mutation: a sent operation's result can be
unknown. `sent_outcome_known: false` describes that uncertainty; the existing
browser exposes a transport error, not a new native outcome enum. Terminal
bytes and arbitrary lifecycle calls are not replayed. A
workspace switch disposes the old link, rejects pending calls with `closed`,
and creates a fresh workspace UI/state; page-level status text is separate.

## Validation

From the repository root:

```sh
bun fixtures/native/actions/check.ts --wire --print-wire
```

The checker validates JSONL IDs, contexts, source anchors, real error codes,
confirmation coverage, channel table and current timeout values. It executes
the current pure web command/parser/route code for applicable cases. Its Rust
probe builds the existing `crew-core` library, decodes the requests using real
`Request`/`Call` types and compares canonical serialized bytes against
`request-bytes.jsonl`. No new Cargo manifest or product test is required;
temporary probe output stays in ignored `.cache/`.

QA can set `CREW_NATIVE_FIXTURE_CACHE` to a shared output root; the action
checker writes its probe under that root's `actions/` subdirectory. Relative
roots resolve against the repository root. Set `CARGO_TARGET_DIR` separately
to keep Cargo output in the same validation area:

```sh
CREW_NATIVE_FIXTURE_CACHE=target/native-validation/fixture-cache CARGO_TARGET_DIR=target/native-validation/cargo bun fixtures/native/actions/check.ts --wire
```

On NixOS, use the repository development shell for the C linker:

```sh
nix-shell --run 'bun fixtures/native/actions/check.ts --wire --print-wire'
```

`request-bytes.jsonl` records `case_id`, `call_index`, numeric envelope ID 7,
canonical `request` and exact compact `json` bytes from `serde_json`. Browser
calls may omit default/null params that Rust serialization includes. The
canonical bytes prove Rust serialization compatibility; the source cases
separately preserve the browser's exact supplied params. Byte equality is not
claimed for differently ordered JSON objects or omitted defaults.

Regenerate bytes only after deliberately reviewing source/fixture changes:

```sh
bun fixtures/native/actions/check.ts --write-wire
```

Daemon and dialog expectations are source-grounded test vectors. This local
checker does not claim end-to-end action, native shell or Apple verification;
those belong to implementation conformance and platform acceptance suites.

`native/terminal-routing.json` is separately tagged to the approved native
terminal contract at `986dcb8c`, with the one-way write correction at `d8a762b9`.
Its ten cases cover two attachments, scoped
input/resize, local close, stale IDs, unacknowledged Attach, scope retirement and
duplicate close delivery. `crew-client/tests/terminal_schema.rs` validates real
record construction/serialization, including `ClosedLocally` and
`AttachmentEnded` and `SentUnacknowledged`. Successful terminal writes complete
only after `FullyWritten`, without a daemon reply; a late error ends that
attachment and cannot create a second operation outcome. Planner and driver
consumers must execute those behavior
cases before their own acceptance. These native rules do not modify the baseline
web cases or the existing 64 request-byte goldens.
